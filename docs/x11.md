# Embedded X11

MagicDesk packages its [Termux:X11 fork](https://github.com/mekhontsev/magicdesk-x11)
as an Android library. The **X11** built-in tool opens a retained X server in an
ordinary MagicDesk window. The standalone Termux:X11 APK is not required.
The selected Termux package still supplies the execution environment, programs
and keyboard data. Enable its external-command support, grant `RUN_COMMAND`,
and install `xkeyboard-config` plus the desired X applications in Termux.

The **X11** tool opens the session manager. **New X11 session** creates a named
session, optionally with a startup command, and opens its desktop in a separate
content-only window. Selecting a retained session reopens its desktop. Session
controls, including **X11 windows**, **Run command** and **Stop X11 session**, stay
in the manager; application and whole-desktop windows have no MagicDesk toolbar.
**Run command** runs another command with that session's `DISPLAY`
and `XAUTHORITY`. Commands are explicit shell scripts in the selected Termux
environment. A full X desktop needs its own window manager/session command.
Closing a whole-session Android window retains the server and its clients; reopen **X11**
and select the session. **Stop X11 session** terminates that server. Separate
sessions have separate X sockets, authorization cookies and input focus.

## Applications

Start includes graphical applications discovered from the selected Termux's
`$XDG_DATA_HOME/applications` (default `~/.local/share/applications`) and
`$PREFIX/share/applications`. User entries take precedence, including hidden
entries that mask installed launchers. The catalog is refreshed when Start is
opened; it does not scan through a privileged filesystem service.

Launching one creates a dedicated X session and an ordinary Android window for
its first mapped client. Additional main windows are presented separately by
the focused host. X transients and toolkit popups are composited with their
owner, not treated as independent Android applications. Closing an individual
Android window requests `WM_DELETE_WINDOW`; the X application may ask to save
or refuse to close. Such a client can be reopened from **X11 windows**. A
dedicated application session stops after its last catalogued window is gone.
A whole-session host instead retains its server until explicit Stop.
Client titles and `_NET_WM_ICON` images appear in task descriptions, the taskbar
and application pickers. Missing or invalid icons retain the X11 tool fallback;
no Termux icon-file access is required.

Firefox and GIMP can run concurrently without a separate Termux:X11 APK or
an X window manager. Applications still retain their own single-instance and
profile-locking rules. Full X desktops use a separate retained session with
their window manager; container launch commands must expose this session's
X socket and Xauthority inside the container. The integration does not install
or configure a proot/chroot distribution automatically.

Custom `.desktop` entries use `X-MagicDesk-ExecBackend=x11`. Their `Exec` is
expanded as desktop-entry arguments, with literal arguments quoted before
execution, rather than implicitly interpreted as shell syntax. Use explicit
`sh -c` for a script. `Terminal=true` uses the existing Termux PTY instead.
Normal shell and Termux entries keep their existing semantics.

## Boundaries

- `X11LaunchSpec` builds the launch environment and private Xauthority input.
  Xorg allocates a free display atomically through `-displayfd`; the host does
  not guess display numbers or poll sockets. Readiness is announced at Xorg's
  `ddxReady`, after allocation and screen/input initialization, not during
  `OsVendorInit`. TCP listening is disabled; `-noreset` retains the server
  generation between client connections.
- `X11Sessions` owns pending admissions, Binder lifetimes, ready renderers and
  explicit shutdown. `MagicDeskRuntimeService` retains this shared service
  independently of Desktop and closes it on runtime exit.
- `X11SessionReceiver` accepts only the selected Termux UID with a fresh,
  pending-session nonce. Android 14's attributed broadcast delivers the sender
  identity. A cancelled or unknown admission cannot start Xorg. Server owner
  death requests normal X shutdown, including socket cleanup.
- Startup has a 60-second deadline, not a retry loop. The host revokes pending
  admission on failure; the server also exits if it never acquires an owner.
- Long-lived X11 commands drain stdout/stderr into a bounded 16 KiB diagnostic
  tail, preserving the command's exit status. Termux does not retain an
  ever-growing GUI application's output. This does not change ordinary Termux
  Console or generic command-result semantics.
- The fork's `X11Session` owns one renderer, socket and Present consumer per
  X server. Its outputs borrow Android Surfaces and select the root X screen
  or an XID. Surface release is acknowledged by the renderer; stopping one
  connection does not terminate another connection's EGL resources.
- `X11ApplicationLaunch` converts the X11 executor into the existing Android
  launch request. `ToolApplications.openSibling` inherits the source task's
  current ownership, not merely the presence of Desktop on that display.
- `X11Activity` and `X11SurfaceView` adapt ordinary Android window, Surface,
  mouse, keyboard and IME lifetimes. The Activity does not own the X server.
  Android input is delivered to the selected output; focus loss releases held
  input. `ToolApplications` owns Android placement, not the X11 renderer.
- The focused Android host owns text clipboard synchronization through
  `AndroidClipboardGateway`. Releasing an older host cannot disable its new
  owner. Transfers are UTF-8, bounded to 1 MiB and handle fragmented socket IO.
- Native window callbacks publish complete catalog snapshots. Surface families
  use Composite pixmaps and shared Damage tracking, with an atomic frame commit
  per output. No periodic Android task scan is introduced.

An X display number, an XID, a renderer output ID and an Android display ID are
distinct identities. Opening X11 does not create an Android display, claim
input routing, acquire HOME or start managed Desktop. Root and Shizuku are not
X-server prerequisites; background or cross-display Android placement retains
the shared launcher's own privileged-service requirements.

## Graphics and Limits

An individual hosted window follows its Android Surface size, including after
a client requests its saved geometry. Multiple views of the same XID have one
size owner: the most recently resized view; the others preserve aspect ratio.
An individual hosted window is kept inside the X root's
input-reachable area, including after client position changes; Composite
rendering alone does not make off-screen pixels reachable by the X pointer.
This does not reposition windows in a whole-desktop output, where the Linux
window manager owns placement. Popup pixels beyond the main output's bounds are clipped.
The Android pointer is used; application-specific X cursor images and clipboard
formats other than text are not presented yet. Catalog titles are bounded to
255 UTF-8 bytes; icons are bounded to 64x64 ARGB pixels; an output family is
bounded to 256 layers.

Android per-app presentation profiles adjust Android task density, not Linux
toolkit DPI. X11 applications currently use their own toolkit/session scaling;
there is no separate persisted MagicDesk DPI profile for each Linux application.

The graphics path retains upstream AHardwareBuffer/EGL support. Linear DRI3
DMA-BUFs can use an optional Vulkan EXA copy accelerator. It loads the system
Vulkan driver lazily, verifies external-memory support, and imports buffers
without replacing the client's storage. Unsupported drivers, ordinary shared
memory and failed imports retain Xorg's CPU copy. Vulkan is not a startup
requirement and adds no bundled driver or library.

Imported resources live with their pixmaps. GPU completion and the existing
renderer lock serialize access to destination HardwareBuffers. When the driver
requires more trailing allocation space than the producer supplied, only the
fitting rows are imported; a small suffix uses a staging upload. This is not a
claim of zero CPU copies on every driver or geometry. There is no screenshot
loop or vendor-specific graphics backend.

The minimum remains API 34. Lint and compilation do not replace Android 14
device testing, which is still pending. The fork's
[embedding contract](../vendor/magicdesk-x11/docs/embedding.md) describes the
library protocol and build requirements; [licensing](licensing.md) covers
corresponding source distribution.
