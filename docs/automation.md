# MagicDesk Automation

MagicDesk provides two adapters over one typed desktop automation gateway:

- a local Model Context Protocol (MCP) server for development tools and user-
  authorized agents;
- Android App Functions for authorized system agents on Android 16 and newer.

Both adapters use the normal MagicDesk session, task, window, and capture
controllers. They do not inject an alternative task policy or expose the
built-in Console as a remote command executor.

## Local MCP Server

The MCP server is disabled by default. Enable **Local MCP automation server**
under **Settings > Automation**. The server exists only while the MagicDesk
runtime service is alive and listens at:

```text
http://127.0.0.1:8765/mcp
```

Every request requires the bearer token generated by MagicDesk. **Copy MCP
connection** copies the endpoint, authorization header, and ADB forwarding
command. **Replace MCP access token** immediately invalidates existing
clients. Diagnostics reports server state and counters but never includes the
token.

For a client running on a connected development computer:

```sh
adb forward tcp:8765 tcp:8765
```

Configure the client for Streamable HTTP at
`http://127.0.0.1:8765/mcp` and set:

```text
Authorization: Bearer <token copied from MagicDesk Settings>
```

A direct protocol check can initialize a stateless session with:

```sh
curl -sS http://127.0.0.1:8765/mcp \
  -H 'Content-Type: application/json' \
  -H "Authorization: Bearer $MAGICDESK_TOKEN" \
  --data '{"jsonrpc":"2.0","id":1,"method":"initialize","params":{"protocolVersion":"2025-11-25","capabilities":{},"clientInfo":{"name":"manual-check","version":"1"}}}'
```

The server supports MCP `initialize`, `ping`, `tools/list`, `tools/call`,
`resources/list`, and `resources/read`. It is stateless and does not require a
session ID.

### Tools and resources

Public tools inspect desktop state, displays, tasks, applications, diagnostics,
self-test results, and recent automation events. They can also start or close a
desktop, launch or focus applications, close tasks, change window mode or
bounds, open Start or Settings, toggle Show Desktop, capture a screenshot, and
wait for an observable state transition. Use `tools/list` for the exact input
schemas.

The following tools are shown only after **Developer automation tools** is
enabled:

- `magicdesk.force_stop_app`
- `magicdesk.run_self_test`
- `magicdesk.send_key`
- `magicdesk.move_pointer`
- `magicdesk.click_pointer`

Read-only resources are available at `magicdesk://state`,
`magicdesk://displays`, `magicdesk://tasks`, `magicdesk://apps`,
`magicdesk://events`, `magicdesk://diagnostics`, and
`magicdesk://self-test`.

Asynchronous actions return when MagicDesk has accepted the request. Agents
should inspect state first and use `magicdesk.wait_for_state` after desktop,
task, or self-test changes instead of assuming a fixed delay.
`magicdesk.launch_app` returns an observed task id when Android publishes the
launched task in time. Task records expose both the native `windowingMode` and
the normalized `mode`, where Android `freeform` is MagicDesk `windowed`.
The active desktop display also exposes its usable `workArea`.

### Security boundary

- The listener binds only to the literal IPv4 loopback address. It never
  listens on Wi-Fi, USB networking, or an external interface.
- A 256-bit token authenticates every request. Comparison is constant-time.
- Browser origins, when supplied, must also identify a literal loopback host.
- Request lines, headers, bodies, concurrent workers, and queued requests are
  bounded.
- Developer tools are separately disabled and are turned off whenever the MCP
  server is disabled.
- ADB forwarding grants access to the host process that owns that forwarding
  connection. Treat the copied token as a password and replace it after
  sharing or recording it accidentally.

## Android App Functions

On Android 16 and newer, MagicDesk publishes these App Functions:

- read desktop state;
- start or close a desktop session;
- launch an Android application in an optional window mode;
- open MagicDesk Settings.

The platform service is protected by
`android.permission.BIND_APP_FUNCTION_SERVICE`, which is reserved for the
Android system. Ordinary third-party applications cannot bind to it directly.
Android 15 keeps the component disabled and continues to use the same MagicDesk
runtime without App Functions.

App Functions deliberately omit force-stop, synthetic input, self-test, raw
shell execution, and direct filesystem operations. Function metadata is
shipped in both the Android 16 legacy and current schemas; a contract test keeps
their stable identifiers synchronized with the Java catalog.

## Development Use

The MCP event resource is a bounded process-local journal of automation action
results. It contains action names, success state, timestamps, and concise
messages, not keyboard text or user file contents. Together with task state,
diagnostics, and `wait_for_state`, it lets an agent drive repeatable debugging
without scraping transient UI or relying on guessed sleeps.

Interactive self-tests still require an awake, unlocked device and a visible
target. MCP can request and observe those tests, but it does not weaken their
preconditions or change their production cleanup path.
