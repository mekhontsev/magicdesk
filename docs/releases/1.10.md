# MagicDesk 1.10

MagicDesk combines native Android Desktop, independent Files and terminal
windows, and permission-controlled local or remote automation.

## Desktop And Displays

- Run Desktop on the phone, a wired monitor, a wireless display, or an owned
  virtual display. View an existing virtual display from a computer with scrcpy.
- Manage displays independently of Desktop sessions: Close Desktop preserves
  the display; Remove display explicitly removes a MagicDesk-owned display.
- Use per-app interface scale, native freeform windows, snap, maximize and
  fullscreen through a shared task controller. Restore now also handles tasks
  made fullscreen through native captions and retains ordinary window geometry.
- During external Desktop, the phone has its own Start launcher with phone
  recents and fullscreen launches. Close returns the previous HOME role and
  surviving desktop tasks to phone fullscreen.
- Physical input uses Android device associations. The phone touchpad and
  Android IME support external editors without a vendor text bridge.

## Files, Terminals And Controls

- Open Files, Android-shell consoles and Termux consoles without starting Desktop.
- Reattach retained terminal sessions and optionally connect to Termux tmux.
  Closing a window does not end its session; process replacement does.
- Scroll terminals by touch, select text with a long press, and adjust font size
  per window or set a default. Terminal input connections and the taskbar's
  initial hardware keyboard layout now follow Android's live state.
- Clipboard, file actions, View/Share intents and application handlers share
  content authorization. Opening a file preserves the app-owned URI grant.
- Settings gains section navigation and dividers. Quick controls is distinct
  from MagicDesk settings. Phone Control Panel is more compact, with display
  selection, output resolution/refresh rate and Wireless grouped together.
- Configure compatible Shizuku and Termux package names; changes apply on restart.

## Automation

- MCP offers separate local and network permissions, file upload/download,
  independent terminal operations and recoverable same-signer APK updates.
- The complete command catalog stays visible across permission changes.
  Self-tests expose exact run IDs, live progress and cleanup status.
- Network MCP is opt-in and uses HTTP, not TLS. Use a trusted network or a
  protected tunnel and grant only the permissions a client needs.

## Requirements And Coverage

- APK: Android 14 / API 34 or newer. Managed Desktop: Android 15 / API 35 or newer.
- Privileged operations require authorized Shizuku; root is not required.
- Native helpers currently target ARM64. Android 14 device validation and full
  work-profile support remain pending; profile-aware identity foundations are in place.
- Compatibility is capability-based, not a guarantee for every firmware.
  The verified OnePlus 5 LineageOS 22.2 scope is documented; application-requested
  immersive fullscreen remains a known limitation (`WINDOW-015`) on that build.
