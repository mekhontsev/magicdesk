# MagicDesk 1.7.0

MagicDesk 1.7.0 expands the project from a device-specific desktop shell into
a broader Android desktop environment while retaining the deeper integrations
available on compatible RedMagic firmware.

## Highlights

- Adds an Android 15 baseline and a Standard Android platform driver. One APK
  and one codebase now select standard or vendor-specific capabilities at
  runtime instead of requiring device forks.
- Adds a built-in shell-powered **Files** application with list and grid views,
  multi-selection, file operations, properties, filtering, drag-and-drop,
  external application handling, APK installation confirmation, and shared
  file/folder workflows with the desktop.
- Adds a persistent multi-window **Console**. Each window owns a real
  `/system/bin/sh` session with its own current directory, history, and
  selectable transcript. Files can open Console in a directory or prepare a
  script without executing it automatically.
- Adds a dedicated **Settings** window for persistent desktop preferences,
  device setup, diagnostics, and About information.
- Keeps live application tasks available when an external desktop is closed
  and restores their previous desktop mode, layout, visibility, and stacking
  when the desktop returns. Tasks closed by Android or the user are not
  relaunched.
- Adds desktop folder shortcuts and unifies file activation, context menus,
  drag-and-drop, and clipboard operations between the desktop and Files.
- Improves phone and launcher isolation while an external desktop is active,
  task handoff between phone and desktop, Alt+Tab and text-focus behavior,
  abrupt-disconnect cleanup, and shell reconnect recovery.
- Expands compatibility diagnostics and the bounded self-test across phone,
  simulated, wired, and wireless displays, including native window, caption,
  placement, focus, and cleanup checks.

## Requirements

- Android 15 / API 35 or newer
- The official Shizuku application with an authorized running service
- One-time **Prepare device** setup and reboot

An external desktop still depends on the wired or wireless display and native
freeform-window capabilities exposed by the device firmware. Optional vendor
features remain disabled when the active platform driver does not provide
them.
